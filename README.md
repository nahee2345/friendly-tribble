## 이번 구현

- 기본 계좌 **미국 일반·한국 일반·ISA 각 1개**, 사용자 추가 계좌는 총 10개 한도
- 시작 4,000,000원: **미국 3,200,000원 / 한국 400,000원 / ISA 400,000원**
- 매월 **25일 350,000원** 가상 입금: **미국 280,000 / 한국 35,000 / ISA 35,000** (기본 정책)
- 계좌 관리 화면에서 **미래 미배분 입금**의 세 계좌 비율 변경 가능 (합계 100%); 이전 이체 불변, 중복 입금 방지
- 미국 주식/ETF Stooq 지연 종가, USD/KRW Frankfurter 참고환율; 필요한 경우 가상 환전·매수를 동일 DB 트랜잭션 처리
- 국내 6자리 종목코드의 비공식 Yahoo Finance 지연 일간 종가: 가격·통화·날짜 검증 실패 시 거래 차단
- ISA에서는 보수적인 국내상장 ETF 허용목록 `069500`, `360750`만 지원 (실제 ISA 전 상품 적격성 검증이 아님)
- 서버 가동 직후와 이후 매시간 자동 검토: 미국 ETF 1주/일 이내(최초 투자금 5% 기준), 국내 일반·ISA 각각 1주/일 이내(계좌별 가격/보유 제한)
- 지연 종가 기준 **-7% / +15%** 가상 매도 검토, 동일 날짜 자동 재매수 제한
- 포트폴리오 현금, 평균취득원가, 미실현/실현 평가, 입금액 제외 수익률 API와 화면. 시세 하나라도 없으면 전체 수익률 확정 금지
- 미국 뉴스 헤드라인 번역: 외부 번역 서비스 2곳 순차 시도, 실패 시 영어 원문/실패 상태 유지
- 최근 30일 자동 거래·검토·건너뛴 이유의 소유자별 일일 보고서
- GitHub Actions에서 Python 집중 테스트 및 React 빌드 검증 자동화

## API 키 없이 가능한 신규 가격 분석 (개발본)

- 미국 ETF·주식 후보의 **가격 분석·백테스트** 버튼을 누르면 서버에서 Stooq 공개 지연 종가를 조회합니다.
- 약 550일 범위의 역사적 종가(최소 65일)로 60거래일 가격 변화, 연율화 변동성, 과거 최대 낙폭, 20/60일 이동평균과 간단한 추세 전략을 계산합니다.
- 백테스트는 **전일 종가까지의 신호 → 다음 종가 가상 체결** 가정이며 거래당 수수료 **10bp**를 가정합니다. 배당, 실제 수수료, 세금, 환율, 슬리피지 및 생존편향은 반영되지 않아 수익 예측/매수 추천이 아닙니다.
- 8개 투자 철학 중 가격 모멘텀 지표만 자동 계산합니다. **가치·성장·배당·분산 등 7개는 검증된 재무/배당/상관 데이터가 없어 미지원으로 명시합니다.**
- 외부 데이터가 끊기거나 가격이 오래되면 `unavailable`을 반환하고 임의의 가격·재무점수를 생성하지 않습니다.
- 미국 시세는 공개 웹 다운로드이므로 한국투자증권 KIS 키가 필요 없습니다. 다만 **인터넷 연결은 필요**합니다.
- 연구용 분석은 모의 주문 의사결정과 독립되어 있습니다. 분석 기능을 추가했다고 투자 알고리즘이 완성됐다는 의미는 아닙니다.

## 입력 최소화·결과 우선 UX (2026-10-17 개발본)

사용자에게 요구하는 주요 설정은 다음 **세 범주**입니다.

1. 8개 투자전략별 비중(합계 100%)
2. 미국 대 한국 주식시장 비중(합계 100%)
3. ETF 대 개별주 비중(합계 100%)

미국·한국·ISA 계좌의 *향후 월별 신규 입금 배분*은 2·3번 설정에서 자동 도출합니다. 이전 원장과 기존 보유종목을 소급 재배정하지 않습니다.

- `GET/POST /api/v1/stage1/strategy-weights`: 사용자별 SQLite 전략 정책을 저장하고 입력을 검증
- `GET /api/v1/stage1/decisions`: 검증된 공개 지연 종가, 가상계좌 잔액·보유 수량과 설정 비중을 사용하여 후보별 계좌, 우선순위, 제한 수량, 현금 유지 목표, 보유기간 및 매도 재검토 조건을 반환
- `GET /api/v1/stage1/news-impact`: RSS 헤드라인에 등장하는 시장·기업 키워드를 **실제 가상 보유종목**과 연결해 관련 뉴스와 잠재 방향을 먼저 표시. 상세 설명·원문은 펼침 항목
- 웹 대시보드에서 매수·현금 유지·보유 관찰 등 **결과를 먼저** 보여 주며, 이유와 위험은 접어서 제시
- 기존 미국 ETF 자동매수의 후보 순위에 8개 전략의 **종목 분류 비중**을 반영합니다. 국내 자동 주문은 한국/ETF 비중이 0이면 건너뜁니다.

**중요한 한계:** 현재 우선순위는 설정 비중과 사전 분류 기반이며 재무제표·기업가치·뉴스의 확정된 가격 영향을 예측하는 모델이 아닙니다. 기사 제목의 방향성 키워드는 인과관계를 증명하지 않습니다. '예상 매도 시기'는 확정 날짜나 가격이 아니라 조건부 재검토 기간입니다. 고급 8전략 정량 운용 및 검증된 종합 자동매매는 여전히 미완성입니다.

## 운용 UX: 사용자 설정 3가지와 결과 우선 보고

2026-10-17 변경: 사용자가 입력할 주요 항목은 **8개 투자전략 비중**, **미국/한국 비중**, **ETF/개별주 비중**뿐입니다. 계좌별 월 적립금 배분은 미국 비중과 한국 비중의 ETF/개별주 비율에서 자동 도출하며, 기존 이체는 소급 변경하지 않습니다.

- `/api/v1/stage1/strategy-weights`에서 8전략 합계 100%를 사용자별 저장
- `/api/v1/stage1/decisions`에서 보유종목 우선, 후보별 검증된 가격·가상계좌·매수 검토 수량·제안 현금 유보액·조건부 매도 재검토 기간·선정 이유 제공
- 뉴스 탭 `/api/v1/stage1/news-impact`에서 **관련 종목/잠재 영향 방향을 먼저** 표시하고, 뉴스 제목·원문·판단 근거는 펼침으로 제공
- 기존 미국 ETF 자동모의매수의 순서를 설정된 전략의 **종목 유형 매칭 비중**으로 조절하며 국내 모의매수도 한국/ETF 비중이 0이면 거절
- 미국·국내 계좌의 자동 신규 가상 매수 시 전략 비중에 따른 보수적 현금 유보율을 사용

**중요:** 재무·배당·기업가치·뉴스 본문 정보를 충분히 검증하지 못하면 '최적 종목', '가장 높은 예상이익', '확정 매도시점', '뉴스의 실제 가격 영향'을 단정하지 않습니다. 현재 투자 우선순위는 기본 상품 분류와 정책 일치도에 근거한 제한적인 모델입니다. 뉴스 영향 역시 **제목 키워드 매칭과 위험 신호 검토**이며, 기사 전체 분석·가격 인과 검증 및 완전 자동 전략 최적화는 미완성입니다. 상품별 세제 검증 없이 ISA의 실제 세후 이익을 단정하지 않습니다.

## 금융 API 연결 전 안전 기반 (2026-10-17)

이번 변경은 **증권사 API/실제 계좌와 분리된 로컬 모의계좌**에만 적용됩니다.

- 지난 실행에서 발견된 React JSX 구문 오류를 재구성. 자동매매 설정 0% 테스트도 새 기준에 맞춤
- PAPER 자동매매 **초기 중지(기본 OFF)**: 사용자 본인이 웹에서 '가상 자동매매 시작 허용'을 누른 뒤에만 자동 거래를 진행합니다. 중지하면 재시작 후에도 중지 유지
- 중지 상태를 예약 워커, 수동 주문 HTTP API, 원장의 SQLite 거래 확정 시 재검증하여 중지 도중 새 주문 기록을 차단
- **30만 원 이상 수동 가상주문**은 인증된 사용자 계정의 승인 대기 원장에 저장. 24시간 만료, 승인·거절 사유와 이력을 분리. 사용자 승인만으로 체결되지 않고 시세·잔고·위험을 거래 시점에 재검증
- **8개 전략 적용 후 14일 변경 제한**. 동일 값 재저장은 허용; 실제 시장정보가 필요 없는 SQLite 상태 규칙
- 자동 워커의 긴급중지 상태는 바로 종료되고 별도의 실계좌 주문 연결은 존재하지 않음
- **일일 7개 카드 미리보기**: 요약, 모의자산, 목표 대비 전략 예산, 배당 자료 상태, 위험, 거래 및 판단, 다음 확인. `GET /api/v1/stage1/seven-cards`에서 조회. 데이터 없는 칸에 가상 수익/배당을 채우지 않음
- 현재 카드 생성은 **요청 시 미리보기**이며, 오후 4시 공식 확정 보고서/푸시 알림과 다름
- 기본 사용자 입력 3개 범주(전략 8개 비중, 미국·한국, ETF·개별주) 유지

`tests/test_stage1_controls_cards.py`에서 재시작 후 긴급 중지 유지, 30만원 승인 중복·취소, 14일 전략 변경 제한, 7개 카드 상태를 테스트합니다. GitHub Actions에 등록했지만 실제 최신 Ubuntu 검사 결과가 확인되기 전까지 완료로 판정하지 않습니다.

## 증권사 API·외부 AI 연결 없이 가능한 실행 범위 (2026-10-17)

사용자 설정은 **8전략 비중**, **미국/한국 주식시장 비중**, **ETF/개별주 비중** 3종류로 제한합니다. 기본 가상계좌는 미국 일반, 한국 일반, ISA이며 초기자본 총 4,000,000원, 매월 25일 350,000원 입금합니다. 일반 UI의 수동 계좌추가/주문/환전 입력을 감추고 자동 검토 결과와 거래내역은 조회할 수 있게 했습니다. 안전을 위한 가상자동매매 일시중지/허용 및 거래 승인 기능은 유지합니다.

- 공개 인터넷 접속만으로 미국 Stooq, 한국 Yahoo 비공식 일간 종가, Frankfurter 환율의 **인증키 없는** 가격 조회를 시도합니다. **증권사 API 키가 없는 것과 인터넷 없이 최신 가격을 아는 것은 다릅니다.** 최신 검증가격이 없으면 실시장 연동 모의매수는 차단됩니다.
- ETF에 더하여 미국 개별주(AAPL, MSFT) 자동 검토와 한국 개별주(005930, 000660) 자동 검토를 새로 연결했습니다. 개별주별/계좌별 주문 현금·보유 한도와 하루 중복 방지를 적용합니다. 이는 제한된 고정 후보 목록이며 시장 전체 최적 종목 선정은 아닙니다.
- 미국 일반계좌의 ETF 매수, 미국 개별주 매수, 한국 일반계좌 ETF 및 개별주 매수, ISA 내 허용 국내 ETF 가상매수는 **독립적인 계좌 정책**으로 실행됩니다. 설정상 해당 국가나 상품 비중이 0이면 모의매수를 건너뜁니다.
- GitHub Actions에 `tests/test_stage1_stock_sleeves.py`를 추가해 중복 실행, 계좌 배정, 투자 비중 0, 가격 검증 실패를 검사합니다.
- 뉴스 제목·거래일지·투자 의견은 내부 규칙 기반이며 Gemini/Claude를 사용하지 않습니다. **향후 AI 선택적 연결은 별도 작업**입니다.
- 사용자 Claude 구독이나 Gemini 일반 웹 서비스는 API 인증을 자동 제공하지 않습니다. 연결 시 모델별 API 키·요금·접근 권한을 따로 확인해야 합니다.

**정직한 기능 한계:** 현재 미구현/미검증에는 전종목 자동 스크리닝, 감사 가능한 최신 재무제표/배당 데이터 결합, 8개 전략 완전 정량 분석, 백테스트의 배당·세금·슬리피지, 정확한 ISA 세제, 주가 미래 예측, 전원 OFF 상태의 무인 거래가 있습니다. 위 기능에서 자료가 없으면 결과를 추정하거나 주문을 강행하지 않습니다.

## 7단계 개발계획 / 1단계 완료 범위: 원장 보호·기록 구조

이번 변경은 **1/7단계**입니다. 기존 투자전략·주문 결정 알고리즘과 실제 가상 보유자산을 임의 수정하지 않습니다. 기존 SQLite 원장을 재작성하지 않고 별도의 `Stage1 v1` 스키마 레지스트리와 기록 테이블을 추가했습니다.

- **버전 관리·비파괴 마이그레이션:** `stage1_schema_registry`에서 지원 버전을 확인합니다. 이전 버전 원장에 입금·계좌·주문·이체 데이터가 있으면 **마이그레이션 전에** 소유자 전용 백업 폴더(`paper DB 상위 폴더의 ../backups`)에 `stage1-premigration-v0-날짜.sqlite3`의 SQLite 온라인 백업을 생성합니다. 전체 `PRAGMA integrity_check`와 SHA-256 해시 기록 후 원본에 새 테이블·인덱스를 한 트랜잭션으로 적용합니다. 중간 오류가 발생하면 스키마 변경을 취소하며, 백업이 안전하지 않으면 변경을 진행하지 않습니다.
- **버전 불일치 방어:** 지원하지 않는 더 높은 DB 스키마를 만나면 다운그레이드하지 않고 연결을 거부합니다. 성공한 마이그레이션은 재실행해도 추가 백업이나 기존 원장 행 수정 없이 유지됩니다.
- **주문 근거 분리:** 신규 가상 체결은 `stage1_trade_metadata`에도 가격 기준일·출처·미국 자동 환전 시 환율을 **같은 트랜잭션**에서 보존합니다. 확인되지 않은 수수료·세금은 `NULL`로 저장하므로 '무료 거래'로 단정하지 않습니다. 이전 거래의 근거는 소급하여 조작하지 않습니다.
- **회계 이벤트 기반:** `stage1_accounting_events`에는 향후 검증된 배당금·배당세·이자·매매/FX 수수료·정정 이력을 원문 근거와 사용자별 멱등키로 저장할 수 있습니다. `stage1_corporate_events`에는 분할·합병·상장폐지·분사 정보를 기록할 수 있습니다. 새 근거 이벤트는 기본적으로 **미대조 상태**이고, 1단계에서는 현금과 보유수량에 영향을 미치지 않습니다.
- **조회 최적화:** 주문 내역(계좌·일시), 입출금 이체, 회계·기업행위에 인덱스 추가. DB 파일을 통째로 재작성하는 방식이 아닙니다.
- **진단:** 로그인 후 `GET /api/v1/stage1/storage-health` 또는 기존 상세 메뉴의 온라인 백업 화면에서 스키마 버전·SQLite 무결성 검사·계정별 거래 근거 건수·미대조 상태를 확인할 수 있습니다.
- **테스트:** `tests/test_stage1_schema_migration.py`에서 예전 형태의 SQLite 원장을 실제 생성해 이전 행 값과 순서 보존, 자동 백업 파일 해시·무결성·0600 권한, 재시작 멱등성, 미래 버전 거절, symlink 백업 경로 거절, 트랜잭션 오류 롤백, 사용자별 배당/기업행위 중복 기록 방지, 새 거래 근거 저장을 검증합니다.

**운영 지침:** 기존 DB와 WAL/SHM을 수동 삭제하지 마세요. 스키마 변경은 원장 첫 접근 시 자동 실행되므로, 업데이트 전에 프로그램을 정상 종료하고 사용자별 기존 원장과 디스크 여유 공간을 확인하세요. 운영 DB 복원은 아직 제공하지 않으므로, 마이그레이션 오류가 발생하면 기존 원장을 그대로 둔 채 검사 로그를 확인하세요.

**2단계 예정:** 미국·한국 종목·가격·재무·배당·공시·뉴스 데이터를 출처/조회시각/품질/오류 상태별로 캐시·검증하는 수집 엔진. 기존 무료 데이터가 없는 값은 채우지 않습니다. 이후 단계의 자산 정산·매매 알고리즘은 자료 신뢰도와 원장의 재현성이 검증된 뒤에만 활성화합니다.

**점수 정의:** 각 전략은 명시한 고정 기준으로 0~100점의 *과거 자료 연구용 휴리스틱*을 반환합니다. 유저의 8전략 비중으로 가중평균을 산출하되, **검증 가능한 전략 비중 합계가 70% 이상**이고 사용자 설정상 활성 전략을 최소 2개(활성 전략이 1개면 1개) 평가할 수 있어야 최종 정량 점수를 표시합니다. 그렇지 않으면 부분점수만 내부에 보존하며 **자료 부족 · 매수 판단 보류**로 표시합니다. 미평가 전략을 0점·50점으로 채우지 않습니다.

`GET /api/v1/stage1/quantitative`: 고정 후보 및 기존 보유자산(최대 20종)을 일괄 평가, 정량점수·충족률·근거·반대 근거·출처 URL·SHA 표시. `GET /api/v1/stage1/quantitative/{symbol}`: 목록에 있는 개별 종목을 같은 원칙으로 평가. 검색으로 나온 대부분의 새 종목은 수집한 검증 가격/재무자료가 아직 없을 수 있으므로 결과를 보류로 표시할 수 있습니다.

**화면:** 통합 대시보드 후보는 평가에 충분한 자료가 있는 종목의 정량 점수를 우선하고, 추천 카드뉴스에서 사용자 전략별 점수·미평가 사유, 근거·반대 근거, 출처·일자를 자세히 볼 수 있습니다. 홈은 기존 압축 레이아웃을 유지합니다. 이는 **과거 수익률의 미래 예측값도, 자동매매 승인도 아닙니다.** 기존 모의매수·매도 알고리즘은 아직 교체하지 않았으며, 사용자 목표비중·현금·계좌에 따른 최종 주문 계획은 **4단계**에 통합합니다.

**성능·안전:** 최대 96개 자료를 한 번에 읽는 SHA 확인 배치 함수(`latest_many`)를 사용하며, 소스 확인시각과 재무 공시일을 검증합니다. 수집기는 가격/뉴스가 뒤쪽의 과거 가격·배당·재무 수집을 영구적으로 밀어내지 않도록 호출량을 제한한 순환 스케줄을 사용합니다. 분석 루틴은 공개 사이트에 추가 요청하지 않으며 가상계좌와 기존 거래 원장을 수정하지 않습니다.

**잔여 한계:** 현재 국산 상장사 공개 재무의 표준화, 공시 지연 및 정정 재무 항목 전처리, ETF 실편입·비용 원자료, 정밀 위험모델, 학습·검증된 수익 예측 모델은 미완성입니다. 따라서 8개 전략 모두에 항상 점수가 존재하지는 않으며 정량 연구 결과를 무조건 '매수'로 표시해서는 안 됩니다.

## 7단계 개발계획 / 4단계: 단일 통합 포트폴리오·모의투자 엔진

이 변경부터 로컬의 매시간 **실행되는 가상매매**는 더 이상 미국 ETF·개별주·국내 ETF·개별주 4개의 독립 주문 루프를 호출하지 않고 `wealthy_server/stage4_portfolio.py`의 `PortfolioEngine` 하나를 호출합니다. 사용자의 8전략 비중·미국/한국·ETF/개별주 비율을 동일한 전체 포트폴리오 자산 평가에 적용합니다. 구 버전 함수는 기존 테스트·호환성을 위해 남아 있으나 매시간 워커에서 재사용하지 않습니다. 기존 `POST /api/v1/stage1/auto-run`도 새 공통 가드로 연결했습니다.

### 투자 계획 생성 (별도의 읽기 전용 모의자산 분석)

- **공개 자료 수집과 주문은 별도:** Stage 2 SHA 확인 캐시의 USD/KRW 및 종목별 가격을 전체 보유자산 평가에 사용합니다. Stage 3 점수는 종목별 8전략 자료 충족률 70% 이상·유효 평가 점수 70점 이상인 후보만 신규 매수 검토에 사용합니다. 데이터 누락/미분류 보유종목/환율 불명 시 포트폴리오 전체 신규매수를 차단합니다.
- **4개 목표 슬리브:** 미국 ETF, 미국 개별주, 한국 ETF, 한국 개별주 목표 비중을 사용자 시장·종목유형 비중의 곱으로 결정합니다. 보유원가는 평균 매수원가 방식으로 재구성하되, 기존 환전·입금은 이익으로 취급하지 않습니다.
- **현금 및 계좌 구분:** 미국 상장 주식·ETF는 미국 일반 가상계좌, 한국 일반주식은 한국 일반계좌, 국내 ETF는 적격 확인 목록에 있는 경우 ISA 우선·그 외 한국 일반계좌로 배정합니다. **사용자 동의 없는 계좌 간 자동 현금 이체는 하지 않습니다.** 현재 ISA 적격성은 069500·360750 2개 심사목록에 국한됩니다.
- **보수적 매수 최적화:** 각 슬리브 목표부족액, 계좌 가용현금 및 현금유보율, 기존 동일종목 노출, 3단계 정량점수 순위를 고려합니다. 매수는 하루 전체 가상자산 평가액의 5% 이내(최대 50만원), 건별 최대 25만원·30만원 이상 체결 불가, 동일종목 편입 한도 ETF 20%·개별주 10%를 적용합니다. 미국 주식은 기존 원장 구조에 따라 **해당 실행 건당 1주**와 필요시 원화→달러 환전을 원자적으로 기록하고, 국내는 최대 5주를 검토합니다. 고득점이라도 검증된 현금 한도와 목표 비중이 부족하면 매수하지 않습니다.
- **보수적 매도:** 평균 매수가 대비 -7%/+15% 지연 종가 기준 조건에서는 보유수량 매도를 검토합니다. 슬리브 5%p 이상 초과나 종목 집중한도 초과 자체는 **자동 매도 신호가 아니라 재검토 알림**입니다. 30만원 이상 매도는 자동체결하지 않으며 별도의 사용자 승인/주문 경로로 처리합니다. 매도가 예정된 같은 계좌/시장·ETF 유형은 해당 일자 재매수를 억제합니다. 실시간 손절 주문이 아닙니다.
- **거래 시각:** 한국시간 주말은 자동 체결을 중단합니다. 국내/미국 각 거래소의 공휴일·장중 개장 여부를 완벽히 판정하는 공식 거래소 달력은 아직 연결하지 않았습니다.
- **실행 전 재검증:** 새 공개 종가·환율 재조회, 캐시 기준과 최대 3% 편차, 최근 기준일·소스·통화 일치, 현금 유보 재확인, 투자비중 설정 변경 감지, 신규/기존 수동매수 포함 당일 합계 한도, 종목별 보유 집중한도, 기존 긴급 중지와 계좌/잔고 원장 검사. **Stage 2 캐시값으로 모의체결하지 않습니다.** 과거 가격의 마지막 종가와 후보 가격의 차이가 10%를 초과하면 BUY 보류합니다.
- **멱등·장애 방어:** 주문 요청은 사용자·일자·슬리브별 안정 키를 사용하며 `stage4_execution_claims`에 먼저 CLAIMED 기록합니다. 실제 `virtual_orders`로 확인되면 EXECUTED로 표시합니다. 충돌·중도 종료된 CLAIMED 건은 **자동 재실행하지 않고, 로그/상세 화면에 미대조로 남겨 수동 검사**하도록 하여 재시작 시 이중체결을 방지합니다. Stage 4 추가 테이블은 기존 가상거래/입금/승인/전략설정 행을 변경하지 않습니다.

### 사용 방법 · API

- 기본 대시보드: 우측 투자 후보 영역의 **전체 비중 계획**을 눌러 사용자 가상자산, 목표·현재 슬리브 노출, 보류 이유, 제안 주문, 매도 검토를 확인할 수 있습니다. 첫 화면은 **조회용**이며 주문 버튼을 넣지 않았습니다.
- 상세 **자산·설정·보고서**: 통합 모의투자 주문계획에서 **별도 수동 실행 버튼**을 제공합니다. 기본 가상매매 중지인 상태에서는 사용할 수 없습니다. 이전 미국 ETF 단독 실행 버튼은 폐지하고 안내로 대체했습니다.
- 인증 필수 `GET /api/v1/stage1/portfolio-plan`: 읽기용 계획·위험·비중·자료 충족률. `GET /api/v1/stage1/portfolio-plan/history`: CLAIMED/EXECUTED/REJECTED 및 가상 체결대조. `POST /api/v1/stage1/portfolio-plan/run`: CSRF·긴급중지·원장 검사를 거친 사용자 요청 수동 한 회 실행. 기존 한 회 ETF 경로도 통합 엔진으로 연결됩니다.
- 서버가 켜져 있으면 기존 매시간 백그라운드 워커도 동일 엔진을 사용합니다. **서버/PC가 꺼져 있으면 자동 운용하지 않습니다.**
- 검증: `tests/test_stage4_portfolio.py`에서 현금 부족, 대상·자료 검증, 최종 시세·FX 변동, 전체 당일 한도, 수동거래 반영, 동일날짜 중복 실행, 미대조 주문, 위험 매도·주말 체결 억제, 긴급정지 동시 발생을 재현합니다.

**제한 및 5단계 과제:** 실제 수수료·세금·배당 정산, 환차손익 분리, TWR·XIRR 성과 계산, ETF 실편입 구성·정밀 공분산 위험모형, 휴장일 달력·시장가/체결 지연을 반영한 백테스트, 가상주문 미대조의 운영자 승인 복원 기능은 미완성입니다. 정량점수는 고정 규칙의 위험·자료 충족 검토값이지 미래 수익률 추정이 아닙니다.

## 7단계 개발계획 / 5단계: 원장검증 회계·성과·세후 시나리오

| 배당 | 검증된 배당락일 공개 이벤트와 해당 날짜 **직전 보유수량**을 비교해 지급 권리 가능성·출처 URL 표시 | 지급일·원천징수·현금 입금 미확인; 배당 현금을 가상 잔고에 넣지 않음 |

**중요:** 국내상장 해외지수 ETF의 실제 배당소득 과세는 `매매차익`과 `과표기준가 증분` 등을 비교하는 규칙, 보유기간 과세 및 다른 금융소득의 영향을 받습니다. 위 세금은 **기준가 자료 없이 단순 매매차익으로 근사한 가정**이므로 실제 원천징수액과 다릅니다. ISA는 금융기관별 가입조건·보유기간·비과세 유형·손익통산·만기 등을 검증해야 하며, 일반계좌와 모든 종목을 1:1로 비교할 수 없습니다.

2026 과세구분 참고: 국회예산정책처의 [2026 대한민국 조세](https://korea.nabo.go.kr/board/file/down.do?fid=33319156), 운용사 안내 [중개형 ISA 과세](https://www.samsungfund.com/etf/pension/isa.do). **외부 고시의 사후 변동 여부는 실사용 전에 재확인**해야 합니다.

### 자료 검증과 잔고 보호

- **원장 불변:** Stage5가 사용하는 `stage1_events`, `virtual_orders`, `stage1_trade_metadata`, `stage1_accounting_events`를 자동 수정하지 않습니다. 실제 배당입금·예상 수수료·예상 납세액을 가상 계좌 현금에 기록하지 않습니다.
- 기존 Stage1 기업행사 테이블의 주식분할·합병 기록은 자동 수량조정 엔진이 없으므로 `RECONCILED`라고 쓰여 있더라도 평가를 보류합니다. 실제 주문원장의 보유수량을 임의로 바꾸지 않습니다.
- **전문 통화 분리:** 역사적 USD 가격손익은 USD로, 원화 주가효과와 원화 FX 효과는 양쪽 FX 원가 근거가 있을 때에만 제공됩니다. 외화 현금의 취득 원가와 전체 포트폴리오의 환차손익 귀속은 별도 회계시스템 없이는 확정되지 않습니다.
- `stage5_nav_snapshots`: 16:00 KST 이후 평가가 모두 확인될 때에만 하루 1회 기록합니다. 관측일·출처 SHA-256·거래원장 SHA-256·스냅샷 SHA-256을 기록하고, 저장 전 SQLite `BEGIN IMMEDIATE` 구간에서 가상원장 변경 여부를 대조합니다. 손상된 기록은 TWR/그래프 근거로 사용하지 않습니다. 이전 5열 테이블이 이미 있었다면 메타데이터 컬럼은 비파괴적으로 추가하고, 유실된 과거 체크섬은 미검증으로 유지합니다.
- **원본·근거 확인:** `GET /api/v1/stage1/accounting`는 로그인한 소유자에 한해 소스 URL/기준일, 원장 기준 세전 손익, 수익률 미산정 사유, ISA 비교 가정 등을 조회합니다. `POST /api/v1/stage1/accounting/capture`는 로그인·CSRF·검증이 완료된 당일 스냅샷만 저장합니다. 기존 종목 주문 API·승인·긴급중지 및 Stage4 현금한도는 변경하지 않습니다.
- **웹 구성:** 첫 화면의 자산흐름에 **검증된 실제 기록 NAV가 두 개 이상 있는 경우 그 자료를 우선** 표시하고, XIRR/세전 총손익을 작게 표시합니다. 자세한 주가손익·환율효과·배당 근거·ISA와 일반계좌 비교는 **읽기용 팝업**으로 열립니다. 상세 워크스페이스에서 정밀회계와 NAV 저장 동작을 조회할 수 있습니다. 홈 화면의 스크롤 없는 설계와 매매 버튼 분리는 유지합니다.
- **일일 7장 카드뉴스:** 확인된 평가금액·세전 총손익·입금일 반영 XIRR, 배당락일 권리 가능성과 지급 미검증 사유를 카드에 표시합니다.

### 남은 범위 (6~7단계 또는 외부 API)

세무 신고 수준의 실제 계좌별 과표기준가·원천징수·ISA 계좌 전체 순소득/세제 자격, 수수료·슬리피지·환전 스프레드 실제 반영, 입금 전후 모든 날짜의 정밀 TWR, 기업행사 분할 재고·원가 자동 조정, verified 지급일에 근거한 배당 가상 현금 정산, 정밀 성과 귀속 및 거래소별 시장 휴장일 캘린더는 미구현입니다. **현재 결과를 실제 세후수익률 또는 세금 납부액으로 부르지 않습니다.**

## 7단계 개발계획 / 6단계: 보유자산 위험·상관관계·스트레스·과거 신호 검증

**이 단계는 공개 지연가격과 1~5단계 원장만 사용하는 가상 투자 전용 분석입니다. 외부 AI나 증권사 API 키는 필요 없습니다.** `wealthy_server/stage6_risk.py`에 읽기 전용 RiskEngine을 만들고, 기존 4단계 통합 모의매수 계획에는 **위험할 때 매수량을 줄이거나 차단하는 방향만** 연결했습니다. 기존 손절/익절, 승인, 가격 재검증, 기본 거래 중지 및 당일 매수 한도는 유지합니다. 이 단계의 위험 점수만으로 자동 매도하지 않습니다.

### 6단계 계산 규칙과 자료 충족 조건

| 지표 | 계산 방식과 자료 기준 | 해석상 제한 |
|---|---|---|
| 종목별 변동성 | 검증된 최근 63개 일간 수익률의 표본표준편차 × √252 | 최근 64종가 이상 필요. 미래 변동성 예측 아님 |
| 최대낙폭 | 해당 63개 일간 수익률의 누적 가치에서 이전 고점 대비 최대 하락 | 장중 낙폭이 아닌 일별 종가 기준 |
| 하위 5% 일간 수익률 | 최근 63개 일간 수익률 중 하단 5% 순서통계 및 해당 꼬리 평균 | 미래 95% VaR 보장이나 확률예측 아님 |
| 종목 간 상관관계 | **같은 통화** 보유종목 중 일자가 일치하는 최소 60개 일간 수익률의 피어슨 상관계수 | USD와 KRW를 FX 이력 없이 혼합하지 않음. 상관 0.90 이상은 주의 |
| 현재 투자 집중도 | 현재 검증 평가금액 / **총 보유 투자자산 가치** | 현금 포함 전체 자산 비중과 다름. 25% 초과는 주의 |
| ETF 지수 중복 가능성 | VOO·360750 등 **고정된 기초지수 식별정보**로 중복 가능성 표시 | 실제 편입종목·구성비율을 모으지 않았으므로 중복 노출 % 계산 불가 |
| 통화별 투자 위험 | 동일 통화 보유종목의 **현재 금액 비중 고정·일별 재조정 가정** 포트폴리오 가격 수익률 | 실제 보유이력·거래비용·배당은 재현하지 않음 |
| 통합 원화 과거 위험 | **미산정** | 시점별 실제 보유수량/과거 FX 경로가 없어 마치 정확한 수치인 것처럼 계산하지 않음 |
| 스트레스 시나리오 | 개별주 -20%, ETF -12%, 미국상장 USD/KRW -7% **동시** 가정, 미국상장 종목은 곱셈 충격 반영 | 확률을 부여하지 않는 가상 충격. 국내상장 해외ETF 실제 환노출은 미검증. 현금 제외 |
| 고정 규칙 모멘텀 과거 재현 | 최근 30거래일, 20·60 종가 이동평균을 **전날 종가까지** 계산해 다음 거래일 수익률에 적용, 전환마다 0.1% 가정 비용 | 최소 95개 일간 가격. 단일종목·후향 재현이며 미래 성과/실제 포트폴리오 백테스트 아님. 실제 거래체결·세금·배당·환전·슬리피지 제외 |

**주문에 연결되는 범위:** 신규 종목의 검증된 일간 종가가 65개 미만이면 **자동매수 보류**. 연환산 과거 변동성 85% 이상 또는 최근 고점 대비 낙폭 -30% 이하이면 **신규매수 차단**. 변동성 55% 이상 또는 낙폭 -20% 이하인 위험 상승 상태는 기존 건당 최대 25만 원 매수 예산을 **절반**으로 제한합니다. 모든 매수는 실행 직전에 원래의 신규 시세·환율과 가격/과거자료의 SHA 검증을 다시 수행합니다. **이 규칙 자체로 매도를 발생시키거나 긴급중지를 풀지 않습니다.** 원본 데이터 부족·실패는 허위 0% 위험으로 간주하지 않습니다.

**한국 장기 시세 개선:** 기존 `last_30_days` UI 종목 변화 조회와 별도로 `kr_research_history` 1년 Yahoo 비공식 일간 가격 검증 수집기를 마련했습니다. 6자리 종목/거래소 suffix/KRW/65~300개 고유 날짜/기준일/원본 URL을 대조하며, 기존 `MarketStore.validated_snapshot`의 2차 품질 검사도 그대로 적용합니다. 자료 공급 실패는 실패로 기록하고 자동매수는 보류할 수 있습니다. 공급원 응답을 실제 Ubuntu에서 보장하지 않습니다.

**원본 연결 위험 알림:** 서버 정기 작업에서 보유종목의 극단적 낙폭·변동성·동일 통화 고상관 위험을 관찰하여 `stage1_inbox`에 **사용자·위험내용·검증 스냅샷 SHA별 중복 제거 알림**을 남깁니다. 뉴스 제목기반 기존 부정 뉴스 알림과 별개입니다. 상관관계는 **두 종목 모두의 출처 URL과 SHA**를 기록하고, 서버가 중지되어 있으면 감시하지 않습니다. 근거 없는 뉴스-가격 인과 관계나 미래 악재를 단정하지 않습니다.

**웹/API:**
- `GET /api/v1/stage1/risk-review`: 인증된 사용자 본인의 포지션, 위험값/미산정 사유, 시나리오 손실, 상관관계/ETF 중복 가능성, 출처 및 위험 알림을 조회합니다.
- `GET /api/v1/stage1/risk-review/{symbol}`: 공개 종목목록에서 확인된 종목의 단일 종목 변동성·자동매수 위험 게이트·30거래일 모멘텀 과거 재현을 추가하여 조회합니다.
- 통합 대시보드는 기존 스크롤 없는 홈을 유지하고 **위험 알림 카드의 위험분석**을 열어 확인합니다. 추천 종목 카드뉴스에는 6단계 매도 재검토·실제 출처 링크·후향 모멘텀 재현 설명을 추가했습니다.
- `tests/test_stage6_risk.py`: 단위·통합 테스트로 결측/캐시 무결성, 미래 신호 미사용, 동일 통화 상관, 원화 총위험 계산 보류, 스트레스 수치, 소스 2개 연결, 재시작 알림 중복, 위험 시 가상매수 차단 등을 검증합니다.

**다른 전략의 정확한 실제 성과 백테스트는 아직 미구현:** 8개 전략 중 모멘텀 가격 규칙의 **단일종목 과거 재현만** 지원합니다. 가치·성장·배당·우량성장·자산배분·장기지수 전략의 과거 시점별 공시/분할·배당지급·ETF 총보수/리밸런싱/환율 시계열이 충분하지 않아서 동일한 과거 운용 성과를 재현했다고 주장하지 않습니다.

**7/7단계 후속 범위:** 통합 장기 내구성 시험, 시세공급 장애 복구, 현금·주문 원장 사후대조, 실제 Ubuntu Chrome UI 확인, 알고리즘 경계·성능·보안 및 백업/복원 최종 수락 검증. 완전한 실시간 브로커 체결이나 확인되지 않은 공시/세액은 추가하지 않습니다.

## 7단계: 최종 통합 검증·원장 무결성·복원 안전성 (출시 후보)

7단계에는 `wealthy_server/stage7_release.py`의 **비파괴 사용자별 SQLite 읽기 전용 원장 감사**, `GET /api/v1/stage1/release-integrity` 및 `GET /api/v1/stage1/backups/{filename}/verify`를 추가했습니다. 전체 모의투자 전 입금·환전·이체·원장 주문·보유수량·현금잔고·Stage4 미대조 요청·Stage5 일별 NAV 증거 해시를 확인합니다. **차단 오류가 있으면 Stage4 자동 모의주문은 실행하지 않습니다.** 사용자의 거래 기록·정책·승인·인증 DB를 자동 복원하거나 초기화하지 않습니다.

백업은 기존 SQLite backup API로 온라인 생성하고, 허용된 `stage1-paper-<시각>.sqlite3` 파일만 안전한 격리 폴더에 시험 복원합니다. 200MiB 이하의 사본은 임시 SQLite 복원 후 원본/임시 사본의 무결성·사용자별 테이블 행 수를 검사하며, 임시 디렉터리는 제거합니다. 운영 원장은 **교체하지 않습니다.** 계산한 SHA는 이전 신뢰 SHA와 자동 대조되지 않으므로 완전한 위변조 증명은 아닙니다. 관리자 로그인 DB·금융 시세 캐시·자격증명은 이 백업에 포함되지 않습니다.

백그라운드 작업의 `stop()` 제한시간 초과 시 살아 있는 스레드 참조를 유지하여 동일 프로세스에서 **두 번째 자동주문 워커 중복 시작을 막습니다.** CI는 자동 고장 주입 시나리오 및 기존 단계 회귀 테스트와 React 프로덕션 빌드, 쉘 문법을 확인합니다.

**상세 수락시험·Ubuntu 안전 배포 지침:** [STAGE7_RELEASE_CHECKLIST.md](STAGE7_RELEASE_CHECKLIST.md). 사용자 Ubuntu에서 `git pull --ff-only` 후 `bash scripts/stage7_acceptance.sh`로 **임시 테스트 원장만 사용하는** 로컬 점검을 할 수 있습니다. 홈 화면의 ‘자산·설정·보고서 → 계좌 관리’에 감사와 백업 안전검사를 추가했습니다. **실제 Ubuntu Chrome 실사용·공개 자료 실접속·장시간 안정성**은 CI로 검증한 사실이 아니며 출시 후보 상태에서 직접 수락시험이 필요합니다.

## 8단계: 초기 400만원 단일 모의투자·대시보드 실데이터 표시 우선

**초기 4,000,000원은 기존 사용자별 가상 원장에 최초 1회만 입금됩니다.** 사용자 기존 매매·계좌는 초기화하거나 테스트 목적으로 체결하지 않습니다. 8단계에서는 `wealthy_server/stage8_sandbox.py`가 **별도의 임시 가상 SQLite**에서 원래 4단계 통합 투자 엔진을 호출해 일회성 가상매수·주말 차단·주문 중복 방지·7단계 회계 원장 무결성을 검증합니다.

기준 시험 입력은 **인공 지연 종가** VOO $600(고가 매수제외 시험) / SPYM $90(저단가 지수 ETF 시험) / KODEX 200(069500) ₩20,000 / USD/KRW ₩1,400, 투자전략 100% 지수·미국 75%·한국 25%·ETF 100%입니다. 결과: **SPYM 1주 ₩126,000 + 069500 3주 ₩60,000 = 가정 투자 ₩186,000**, 잔여 현금 ₩3,814,000. 하루 매수 한도보다 비싼 VOO는 가정 매수에서 제외됩니다, 원금 ₩4,000,000. 주말 0건, 평일 같은 요청 재실행 0건, 임시 원장 무결성 healthy. **현재 실제 주가/투자 추천/실제 사용자의 모의 체결 결과가 아닙니다.** 전체 원금 5%인 하루 20만원 매수 상한을 그대로 유지합니다. 저가 단위 미국 S&P 500 ETF SPYM은 발행사에서 상품 정체성을 확인했지만, 실제 지연 종가·환율을 별도 검증하기 전에는 SPYM도 주문하지 않습니다. VOO와 SPYM을 둘 다 보유할 경우 같은 S&P 500 지수의 중복 노출 위험을 표시합니다.

인증된 `GET /api/v1/stage1/stage8-simulation`의 `actual_owner` 필드는 실제 로그인 사용자의 자금·현금·보유현황, `scenario`는 합성 예시 결과입니다. 첫 화면 상단에서 실제 입금 및 주말 여부를 별도 표시하고, ‘가정 모의투자 상세’를 클릭해 근거/주문/잔고를 확인합니다. **실제 금융자료나 뉴스가 확인되지 않으면 미확인으로 표시하며 허구의 가격/뉴스를 만들어내지 않습니다.** 초기 현금 외에 실제 보유자산 평가가 미확정이면 총자산을 임의 확정하지 않습니다.

[8단계 단일 사이클 투자 검증/Ubuntu 점검 안내](STAGE8_400M_REHEARSAL.md). `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q tests/test_stage8_sandbox.py`로 독립 검증용 테스트를 재현할 수 있습니다. GitHub CI는 실제 Ubuntu Chrome·외부 공급원 실접속·다일 자동운용까지 증명하지 않습니다.
