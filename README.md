## 이번 구현

- 기본 계좌 **미국 일반·한국 일반·ISA 각 1개**, 사용자 추가 계좌는 총 10개 한도
- 시작 4,000,000원: **미국 3,200,000원 / 한국 400,000원 / ISA 400,000원**
- 매월 **25일 350,000원** 가상 입금: **미국 280,000 / 한국 35,000 / ISA 35,000** (기본 정책)
- 계좌 관리 화면에서 **미래 미배분 입금**의 세 계좌 비율 변경 가능 (합계 100%); 이전 이체 불변, 중복 입금 방지
- 미국 주식/ETF Stooq 지연 종가, USD/KRW Frankfurter 참고환율; 필요한 경우 가상 환전·매수를 동일 DB 트랜잭션 처리
- 국내 6자리 종목코드의 비공식 Yahoo Finance 지연 일간 종가: 가격·통화·날짜 검증 실패 시 거래 차단
- ISA에서는 보수적인 국내상장 ETF 허용목록 `069500`, `360750`만 지원 (실제 ISA 전 상품 적격성 검증이 아님)
- 서버 가동 직후와 이후 매시간 자동 검토: 미국 ETF 1주/일 이내(최초 투자금 5% 기준), 국내 일반·ISA 각각 1주/일 이내(계좌별 가격/보유 제한)
- 지연 종가 기준 **-7% / +15%** 가상 매도 검토, 동일 날짜 자동 재매수 제한
- 포트폴리오 현금, 평균취득원가, 미실현/실현 평가, 입금액 제외 수익률 API와 화면. 시세 하나라도 없으면 전체 수익률 확정 금지
- 미국 뉴스 헤드라인 번역: 외부 번역 서비스 2곳 순차 시도, 실패 시 영어 원문/실패 상태 유지
- 최근 30일 자동 거래·검토·건너뛴 이유의 소유자별 일일 보고서
- GitHub Actions에서 Python 집중 테스트 및 React 빌드 검증 자동화

## API 키 없이 가능한 신규 가격 분석 (개발본)

- 미국 ETF·주식 후보의 **가격 분석·백테스트** 버튼을 누르면 서버에서 Stooq 공개 지연 종가를 조회합니다.
- 약 550일 범위의 역사적 종가(최소 65일)로 60거래일 가격 변화, 연율화 변동성, 과거 최대 낙폭, 20/60일 이동평균과 간단한 추세 전략을 계산합니다.
- 백테스트는 **전일 종가까지의 신호 → 다음 종가 가상 체결** 가정이며 거래당 수수료 **10bp**를 가정합니다. 배당, 실제 수수료, 세금, 환율, 슬리피지 및 생존편향은 반영되지 않아 수익 예측/매수 추천이 아닙니다.
- 8개 투자 철학 중 가격 모멘텀 지표만 자동 계산합니다. **가치·성장·배당·분산 등 7개는 검증된 재무/배당/상관 데이터가 없어 미지원으로 명시합니다.**
- 외부 데이터가 끊기거나 가격이 오래되면 `unavailable`을 반환하고 임의의 가격·재무점수를 생성하지 않습니다.
- 미국 시세는 공개 웹 다운로드이므로 한국투자증권 KIS 키가 필요 없습니다. 다만 **인터넷 연결은 필요**합니다.
- 연구용 분석은 모의 주문 의사결정과 독립되어 있습니다. 분석 기능을 추가했다고 투자 알고리즘이 완성됐다는 의미는 아닙니다.

## 입력 최소화·결과 우선 UX (2026-10-17 개발본)

사용자에게 요구하는 주요 설정은 다음 **세 범주**입니다.

1. 8개 투자전략별 비중(합계 100%)
2. 미국 대 한국 주식시장 비중(합계 100%)
3. ETF 대 개별주 비중(합계 100%)

미국·한국·ISA 계좌의 *향후 월별 신규 입금 배분*은 2·3번 설정에서 자동 도출합니다. 이전 원장과 기존 보유종목을 소급 재배정하지 않습니다.

- `GET/POST /api/v1/stage1/strategy-weights`: 사용자별 SQLite 전략 정책을 저장하고 입력을 검증
- `GET /api/v1/stage1/decisions`: 검증된 공개 지연 종가, 가상계좌 잔액·보유 수량과 설정 비중을 사용하여 후보별 계좌, 우선순위, 제한 수량, 현금 유지 목표, 보유기간 및 매도 재검토 조건을 반환
- `GET /api/v1/stage1/news-impact`: RSS 헤드라인에 등장하는 시장·기업 키워드를 **실제 가상 보유종목**과 연결해 관련 뉴스와 잠재 방향을 먼저 표시. 상세 설명·원문은 펼침 항목
- 웹 대시보드에서 매수·현금 유지·보유 관찰 등 **결과를 먼저** 보여 주며, 이유와 위험은 접어서 제시
- 기존 미국 ETF 자동매수의 후보 순위에 8개 전략의 **종목 분류 비중**을 반영합니다. 국내 자동 주문은 한국/ETF 비중이 0이면 건너뜁니다.

**중요한 한계:** 현재 우선순위는 설정 비중과 사전 분류 기반이며 재무제표·기업가치·뉴스의 확정된 가격 영향을 예측하는 모델이 아닙니다. 기사 제목의 방향성 키워드는 인과관계를 증명하지 않습니다. '예상 매도 시기'는 확정 날짜나 가격이 아니라 조건부 재검토 기간입니다. 고급 8전략 정량 운용 및 검증된 종합 자동매매는 여전히 미완성입니다.

## 운용 UX: 사용자 설정 3가지와 결과 우선 보고

2026-10-17 변경: 사용자가 입력할 주요 항목은 **8개 투자전략 비중**, **미국/한국 비중**, **ETF/개별주 비중**뿐입니다. 계좌별 월 적립금 배분은 미국 비중과 한국 비중의 ETF/개별주 비율에서 자동 도출하며, 기존 이체는 소급 변경하지 않습니다.

- `/api/v1/stage1/strategy-weights`에서 8전략 합계 100%를 사용자별 저장
- `/api/v1/stage1/decisions`에서 보유종목 우선, 후보별 검증된 가격·가상계좌·매수 검토 수량·제안 현금 유보액·조건부 매도 재검토 기간·선정 이유 제공
- 뉴스 탭 `/api/v1/stage1/news-impact`에서 **관련 종목/잠재 영향 방향을 먼저** 표시하고, 뉴스 제목·원문·판단 근거는 펼침으로 제공
- 기존 미국 ETF 자동모의매수의 순서를 설정된 전략의 **종목 유형 매칭 비중**으로 조절하며 국내 모의매수도 한국/ETF 비중이 0이면 거절
- 미국·국내 계좌의 자동 신규 가상 매수 시 전략 비중에 따른 보수적 현금 유보율을 사용

**중요:** 재무·배당·기업가치·뉴스 본문 정보를 충분히 검증하지 못하면 '최적 종목', '가장 높은 예상이익', '확정 매도시점', '뉴스의 실제 가격 영향'을 단정하지 않습니다. 현재 투자 우선순위는 기본 상품 분류와 정책 일치도에 근거한 제한적인 모델입니다. 뉴스 영향 역시 **제목 키워드 매칭과 위험 신호 검토**이며, 기사 전체 분석·가격 인과 검증 및 완전 자동 전략 최적화는 미완성입니다. 상품별 세제 검증 없이 ISA의 실제 세후 이익을 단정하지 않습니다.

## 금융 API 연결 전 안전 기반 (2026-10-17)

이번 변경은 **증권사 API/실제 계좌와 분리된 로컬 모의계좌**에만 적용됩니다.

- 지난 실행에서 발견된 React JSX 구문 오류를 재구성. 자동매매 설정 0% 테스트도 새 기준에 맞춤
- PAPER 자동매매 **초기 중지(기본 OFF)**: 사용자 본인이 웹에서 '가상 자동매매 시작 허용'을 누른 뒤에만 자동 거래를 진행합니다. 중지하면 재시작 후에도 중지 유지
- 중지 상태를 예약 워커, 수동 주문 HTTP API, 원장의 SQLite 거래 확정 시 재검증하여 중지 도중 새 주문 기록을 차단
- **30만 원 이상 수동 가상주문**은 인증된 사용자 계정의 승인 대기 원장에 저장. 24시간 만료, 승인·거절 사유와 이력을 분리. 사용자 승인만으로 체결되지 않고 시세·잔고·위험을 거래 시점에 재검증
- **8개 전략 적용 후 14일 변경 제한**. 동일 값 재저장은 허용; 실제 시장정보가 필요 없는 SQLite 상태 규칙
- 자동 워커의 긴급중지 상태는 바로 종료되고 별도의 실계좌 주문 연결은 존재하지 않음
- **일일 7개 카드 미리보기**: 요약, 모의자산, 목표 대비 전략 예산, 배당 자료 상태, 위험, 거래 및 판단, 다음 확인. `GET /api/v1/stage1/seven-cards`에서 조회. 데이터 없는 칸에 가상 수익/배당을 채우지 않음
- 현재 카드 생성은 **요청 시 미리보기**이며, 오후 4시 공식 확정 보고서/푸시 알림과 다름
- 기본 사용자 입력 3개 범주(전략 8개 비중, 미국·한국, ETF·개별주) 유지

### 추가한 자동 점검

`tests/test_stage1_controls_cards.py`에서 재시작 후 긴급 중지 유지, 30만원 승인 중복·취소, 14일 전략 변경 제한, 7개 카드 상태를 테스트합니다. GitHub Actions에 등록했지만 실제 최신 Ubuntu 검사 결과가 확인되기 전까지 완료로 판정하지 않습니다.

## 증권사 API·외부 AI 연결 없이 가능한 실행 범위 (2026-10-17)

사용자 설정은 **8전략 비중**, **미국/한국 주식시장 비중**, **ETF/개별주 비중** 3종류로 제한합니다. 기본 가상계좌는 미국 일반, 한국 일반, ISA이며 초기자본 총 4,000,000원, 매월 25일 350,000원 입금합니다. 일반 UI의 수동 계좌추가/주문/환전 입력을 감추고 자동 검토 결과와 거래내역은 조회할 수 있게 했습니다. 안전을 위한 가상자동매매 일시중지/허용 및 거래 승인 기능은 유지합니다.

- 공개 인터넷 접속만으로 미국 Stooq, 한국 Yahoo 비공식 일간 종가, Frankfurter 환율의 **인증키 없는** 가격 조회를 시도합니다. **증권사 API 키가 없는 것과 인터넷 없이 최신 가격을 아는 것은 다릅니다.** 최신 검증가격이 없으면 실시장 연동 모의매수는 차단됩니다.
- ETF에 더하여 미국 개별주(AAPL, MSFT) 자동 검토와 한국 개별주(005930, 000660) 자동 검토를 새로 연결했습니다. 개별주별/계좌별 주문 현금·보유 한도와 하루 중복 방지를 적용합니다. 이는 제한된 고정 후보 목록이며 시장 전체 최적 종목 선정은 아닙니다.
- 미국 일반계좌의 ETF 매수, 미국 개별주 매수, 한국 일반계좌 ETF 및 개별주 매수, ISA 내 허용 국내 ETF 가상매수는 **독립적인 계좌 정책**으로 실행됩니다. 설정상 해당 국가나 상품 비중이 0이면 모의매수를 건너뜁니다.
- GitHub Actions에 `tests/test_stage1_stock_sleeves.py`를 추가해 중복 실행, 계좌 배정, 투자 비중 0, 가격 검증 실패를 검사합니다.
- 뉴스 제목·거래일지·투자 의견은 내부 규칙 기반이며 Gemini/Claude를 사용하지 않습니다. **향후 AI 선택적 연결은 별도 작업**입니다.
- 사용자 Claude 구독이나 Gemini 일반 웹 서비스는 API 인증을 자동 제공하지 않습니다. 연결 시 모델별 API 키·요금·접근 권한을 따로 확인해야 합니다.

**정직한 기능 한계:** 현재 미구현/미검증에는 전종목 자동 스크리닝, 감사 가능한 최신 재무제표/배당 데이터 결합, 8개 전략 완전 정량 분석, 백테스트의 배당·세금·슬리피지, 정확한 ISA 세제, 주가 미래 예측, 전원 OFF 상태의 무인 거래가 있습니다. 위 기능에서 자료가 없으면 결과를 추정하거나 주문을 강행하지 않습니다.

## 7단계 개발계획 / 1단계 완료 범위: 원장 보호·기록 구조

이번 변경은 **1/7단계**입니다. 기존 투자전략·주문 결정 알고리즘과 실제 가상 보유자산을 임의 수정하지 않습니다. 기존 SQLite 원장을 재작성하지 않고 별도의 `Stage1 v1` 스키마 레지스트리와 기록 테이블을 추가했습니다.

- **버전 관리·비파괴 마이그레이션:** `stage1_schema_registry`에서 지원 버전을 확인합니다. 이전 버전 원장에 입금·계좌·주문·이체 데이터가 있으면 **마이그레이션 전에** 소유자 전용 백업 폴더(`paper DB 상위 폴더의 ../backups`)에 `stage1-premigration-v0-날짜.sqlite3`의 SQLite 온라인 백업을 생성합니다. 전체 `PRAGMA integrity_check`와 SHA-256 해시 기록 후 원본에 새 테이블·인덱스를 한 트랜잭션으로 적용합니다. 중간 오류가 발생하면 스키마 변경을 취소하며, 백업이 안전하지 않으면 변경을 진행하지 않습니다.
- **버전 불일치 방어:** 지원하지 않는 더 높은 DB 스키마를 만나면 다운그레이드하지 않고 연결을 거부합니다. 성공한 마이그레이션은 재실행해도 추가 백업이나 기존 원장 행 수정 없이 유지됩니다.
- **주문 근거 분리:** 신규 가상 체결은 `stage1_trade_metadata`에도 가격 기준일·출처·미국 자동 환전 시 환율을 **같은 트랜잭션**에서 보존합니다. 확인되지 않은 수수료·세금은 `NULL`로 저장하므로 '무료 거래'로 단정하지 않습니다. 이전 거래의 근거는 소급하여 조작하지 않습니다.
- **회계 이벤트 기반:** `stage1_accounting_events`에는 향후 검증된 배당금·배당세·이자·매매/FX 수수료·정정 이력을 원문 근거와 사용자별 멱등키로 저장할 수 있습니다. `stage1_corporate_events`에는 분할·합병·상장폐지·분사 정보를 기록할 수 있습니다. 새 근거 이벤트는 기본적으로 **미대조 상태**이고, 1단계에서는 현금과 보유수량에 영향을 미치지 않습니다.
- **조회 최적화:** 주문 내역(계좌·일시), 입출금 이체, 회계·기업행위에 인덱스 추가. DB 파일을 통째로 재작성하는 방식이 아닙니다.
- **진단:** 로그인 후 `GET /api/v1/stage1/storage-health` 또는 기존 상세 메뉴의 온라인 백업 화면에서 스키마 버전·SQLite 무결성 검사·계정별 거래 근거 건수·미대조 상태를 확인할 수 있습니다.
- **테스트:** `tests/test_stage1_schema_migration.py`에서 예전 형태의 SQLite 원장을 실제 생성해 이전 행 값과 순서 보존, 자동 백업 파일 해시·무결성·0600 권한, 재시작 멱등성, 미래 버전 거절, symlink 백업 경로 거절, 트랜잭션 오류 롤백, 사용자별 배당/기업행위 중복 기록 방지, 새 거래 근거 저장을 검증합니다.

**운영 지침:** 기존 DB와 WAL/SHM을 수동 삭제하지 마세요. 스키마 변경은 원장 첫 접근 시 자동 실행되므로, 업데이트 전에 프로그램을 정상 종료하고 사용자별 기존 원장과 디스크 여유 공간을 확인하세요. 운영 DB 복원은 아직 제공하지 않으므로, 마이그레이션 오류가 발생하면 기존 원장을 그대로 둔 채 검사 로그를 확인하세요.

**2단계 예정:** 미국·한국 종목·가격·재무·배당·공시·뉴스 데이터를 출처/조회시각/품질/오류 상태별로 캐시·검증하는 수집 엔진. 기존 무료 데이터가 없는 값은 채우지 않습니다. 이후 단계의 자산 정산·매매 알고리즘은 자료 신뢰도와 원장의 재현성이 검증된 뒤에만 활성화합니다.
