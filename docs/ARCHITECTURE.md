# 읽기 전용 시장자료 자동화 구조와 권한 경계

확인 기준일: **2026-10-11 (Asia/Seoul)**

이 문서는 구현 설명입니다. 투자 비중·한도·승인 정책은 `PROJECT_RULES.md`만이 원본입니다.
현재 단계는 기존 `A OFFLINE` 기능을 유지하면서 추가된 `A2 DATA_READ_ONLY`입니다. 계좌 조회
단계 B와 주문 단계 C~D2는 활성화하지 않았습니다.

## 두 개의 분리된 데이터 흐름

```text
[사용자 자산 흐름 — 기존]
UTF-8 SAMPLE/MANUAL JSON
  → scenario.py: 엄격한 schema·중복키·Decimal·시간대 검증
  → domain.py / ledger.py: 단일 자료영역·보호자금 분리
  → calculations.py / allocation.py / satellite.py
  → reporting.py: 고정된 7개 절 Markdown
  → CLI 또는 Tk GUI

[공식 시장자료 흐름 — 신규]
공급자 설정 + OS 보안 저장소의 사용자 키
  → providers.py / kr_providers.py: 고정 HTTPS host, timeout, 제한 재시도
  → 공급자별 schema·단위·식별자 검증
  → market_data.py: 정규 레코드와 수집 run을 SQLite transaction으로 저장
  → strategy.py: 일반 코드 지표·점수·중복 노출 검사 함수
  → automation.py: KIS 관측 스냅샷의 시점 제한 후보 평가와 7개 절 자동 보고서
  → GUI 표시 또는 scheduler.py의 15:00/16:00 사용자 예약
```

두 흐름은 자동 합산되지 않습니다. 자동 시장자료를 SAMPLE 또는 사용자의 실제 잔고처럼
표시하지 않습니다. 사용자 보유자산·예산이 없으면 자동 보고서의 해당 절은 `미입력`이며,
시장 후보를 볼 수 있어도 수량을 만들지 않습니다.

## 공급자 연결 상태

- `BLS`: v2 URL의 다중 시계열 일괄 POST를 구현했습니다. 등록키가 없으면 v1 호환
  서명·미등록 한도, 등록키가 있으면 v2 확장 한도를 적용합니다. 2026-10-11 실연결은 결측 관측 때문에
  `PARTIAL`이었으며 정상 관측은 저장했습니다.
- `Federal Reserve RSS`: 공식 발표 메타데이터 수집 구현. 2026-10-11 최종 독립 DB
  재검증에서 20건 `OK`였습니다. 일반 기업 뉴스나 기사 본문이 아닙니다.
- `SEC EDGAR`: submissions/companyfacts 구현. 준수 User-Agent와 CIK가 없으면 호출 차단.
- `KIS`: 국내 현재가·거래량·거래대금 읽기 구현. 사용자 App Key/Secret 없으면 호출 차단.
- `OpenDART`: 공시·재무 읽기 구현. 사용자 키·회사 대상 없으면 호출 차단.
- `ECOS`: 통계 읽기 구현. 공식 `sample`은 연결검사만 가능하고 운영 저장에는 사용자 키 필요.
- 계약형 뉴스·ETF 발행사 페이지: 권리가 확인되기 전 비활성, 무단 크롤링 없음.

정확한 이용조건과 실제 테스트 상태는 `DATA_SOURCES.md`를 따릅니다.

## 인증정보 경계

`keyring`을 통해 Ubuntu Secret Service, Windows Credential Manager backend 또는 macOS
Keychain backend만
허용합니다. null/fail/plaintext/third-party fallback은 거부합니다. 저장소를 사용할 수 없거나
잠겨 있으면 해당 공급자만 `설정 필요/오류`로 두며 평문 파일로 대체하지 않습니다.

- KIS 모의(`kis_paper`)와 실전(`kis_live`) 항목을 분리합니다.
- access token은 메모리에만 유지하고 DB·로그·보고서에 저장하지 않습니다.
- SEC 연락 User-Agent도 개인정보가 될 수 있어 같은 보호 저장소를 사용합니다.
- 저장 여부는 상태 조회 때 OS keyring에서만 확인하며 앱 DB에는 비밀이나
  `credential_ref`를 기록하지 않고, 값 자체도 화면에 다시 표시하지 않습니다.
- GUI 비밀 입력칸은 가리고, 저장 시 즉시 비웁니다.
- systemd 사용자 서비스에서는 데스크톱 Secret Service가 잠겨 있을 수 있습니다. 그 경우
  인증 공급자는 실패하고 BLS/Fed 등 무인증 공급자 결과만 부분 보고합니다.

## 시장자료 저장 불변조건

기본 DB는 Linux `$XDG_DATA_HOME/long-term-asset-assistant/market-data.sqlite3` 또는
`~/.local/share/...`, Windows `%LOCALAPPDATA%\LongTermAssetAssistant\...`에 둡니다.
프로젝트 DB는 테스트나 명시적 `--database`에서만 사용하며 release ZIP에서 제외됩니다.

- 연결마다 새 SQLite connection, foreign key, WAL, busy timeout을 적용합니다.
- 수집 run과 성공 레코드는 `BEGIN IMMEDIATE` transaction으로 확정합니다.
- 값은 `REAL`이 아니라 정확한 십진 문자열, 시각은 UTC offset이 있는 ISO 문자열입니다.
- 원시 비밀·HTTP 헤더·요청 URL query는 저장하지 않습니다.
- 새 로컬 데이터 디렉터리와 DB는 POSIX에서 각각 소유자 전용 `0700`/`0600` 권한을 적용합니다.
- `provider/kind/provider_record_id/content_sha256`로 같은 내용을 식별하되 수정본 이력을
  덮어쓰지 않습니다.
- 실패 run도 상태·일반 코드만 기록하고 마지막 정상 레코드는 보존합니다.
- BLS·OpenDART와 공식 한도 미확인 ECOS의 보수적 안전 호출 예약, 수집 lease와 예약 slot claim은 SQLite
  `BEGIN IMMEDIATE`로 같은 DB를 쓰는 프로세스 사이에서 원자적으로 갱신합니다.
- 공식 공표시각이 없는 자료는 첫 수집시각 이후에만 이용해 미래정보 사용을 막습니다.
- 월별 사용자 기록은 검증된 원장의 월·자료영역·기준시각·완전성·합계와 원본 hash만
  보존합니다. 원본 JSON 자체는 복제하지 않습니다.

## 전략과 위험 규칙

전략 혼합은 후보 평가용이고 자산배분과 별도입니다. 합계 100%를 정확한 Decimal로
검사합니다. 가격·거래량·거래대금 시계열로 상대거래량, 6개월 추세, 20일 변동성을 계산할
수 있고, 품질·가치·배당성장 등은 검증된 재무 입력이 있어야 합니다. 하나라도 필요한 자료가
없으면 선택 전략 전체 점수를 0으로 만들지 않고 `UNAVAILABLE`로 둡니다. 현재 자동화는
저장된 KIS 국내 **현재가 관측 스냅샷** 중 보고서 생성 기준시각 이전의 최신 동일
`run_id`·`effective_at`·`collected_at` 관측 묶음만 후보 입력에 사용합니다. 최신 묶음에 일부
지표가 없더라도 같은 날짜의 이전 관측으로 보충하지 않습니다. 공식 종가·거래소 일봉·수정주가라고 부르지 않고, 관측을 누적해
20일 상대거래량·변동성이나 6개월 모멘텀을 산출하지 않습니다.
평가 상태·점수·반대 근거·출처 레코드 ID는 이전 기록을 덮어쓰지 않고 추가 저장하며
자동 보고서 6절에 표시합니다. 아직 재무·공시·허가된 기업 뉴스의 종목별 매핑과 긴 가격
시계열이 없어 대부분의 전략은 평가 불가가 정상입니다.

여러 전략의 종목 배정안에서 같은 종목 노출을 합산해 기본 개별주 5%, ETF 40%, 위성 전체
10% 상한을 검사하는 함수는 구현·단위 테스트했습니다. 그러나 현재 설정은 **전략 비중**만
저장하고 전략별 종목 배정안을 받지 않으므로, 이 합산 검사는 GUI·수집·자동 보고서에 아직
연결되지 않았습니다. ETF 50% 승인 예외나 정책 변경을 자동 적용하지 않습니다. 자동 후보는
상품유형·금지상품 검증 설정이 없으면 `UNAVAILABLE`이며, 현재 검증된 전망 모델이 없어 1년
가격·수익률·확률을 생성하지 않습니다.

## 예약·동시성

Ubuntu는 systemd 사용자 timer 두 개를 생성합니다.

- 15:00 Asia/Seoul: `python -B -m asset_assistant.automation collect`로 수집한 뒤,
  수집 상태가 `OK/PARTIAL`이면 설정된 전략 후보를 같은 기준시각으로 재평가
- 16:00 Asia/Seoul: `python -B -m asset_assistant.automation report`
- `Persistent=true`: 사용자 manager가 다시 동작할 때 놓친 읽기 작업을 한 번 시도
- SQLite 날짜·작업 slot claim: 같은 예약 슬롯 중복 실행 차단
- 같은 DB의 `market_collection` 2시간 lease: GUI·CLI·예약 수집의 동시 공급자 호출 차단
- 실패 slot과 2시간 넘은 `RUNNING` slot은 재시도하며 완료·실패·오래된 시도를 별도 이력에 보존

15시 후보 재평가의 설정·저장 오류는 정상 수집 자료를 지우지 않고 예약 실행을 `PARTIAL`로
기록합니다. 16시 보고서 생성 중 같은 오류가 나도 본문에 미완료 사유를 표시하고 보고서
snapshot과 예약 실행 상태를 `PARTIAL`로 맞춥니다. systemd 단위 파일이 일부만 있거나 enable된
타이머가 현재 active가 아니면 GUI는 `예약 활성`로 단정하지 않고 확인 필요로 표시합니다.

열린 GUI는 시작 후 10초부터 30초마다 새 자동 보고서를 로컬 DB에서 비동기로 확인합니다.
수동 원장 열람 중에는 화면을 덮지 않고 알림만 표시합니다. GUI가 꺼져 있으면 자동 화면
표시는 없으며 다음 실행 때 최신 보고서를 열 수 있습니다.

공급자 상태는 보존된 최신 정상 레코드의 기준·수집시각과 마지막 갱신 시도의 완료시각을
서로 다른 열·문구로 표시합니다. 실패 시도 시각을 정상 자료 수집시각으로 표시하지 않습니다.
시장정보 웹 상태도 마지막 시도·성공·이번 결과·현재 자료 기준을 분리하며, 전체 수집 상한 때문에
시작하지 못한 출처(`NOT_STARTED_TIME_LIMIT`)와 진행 중 시간 초과(`TIMED_OUT`)를 구분합니다.
성공한 자료와 이전 정상 자료는 부분 실패 뒤에도 유지합니다. 수집 상한은 연결·TLS·응답 읽기에
협력적으로 적용되며 운영체제 DNS 해석 호출 자체를 진행 중 강제 취소하지는 못합니다.

시장정보 보존 상태는 최초 수집시각에서 달력 기준 1년으로 계산하고 재수집으로 만료일을
연장하지 않습니다. 만료 전 30일 이내는 표시상 `EXPIRING_SOON`입니다. 만료 미리보기는 DB
snapshot/cursor로 `EXPIRED` 메타데이터만 페이지 조회하며, snapshot 뒤 처음 수집된 행을
후속 페이지와 집계에서 제외합니다. 삭제 API·자동 정리 작업은 없습니다.
정보 항목 수와 다중 출처 기록 수는 별도 단위로 집계합니다.

16시 보고서는 수집이 끝나지 않았거나 대상 날짜 15시 수집 run이 없거나 정상 완료가 아니면
`PARTIAL/미갱신`으로 만들고 이전 자료의 기준·수집시각을 표시합니다. 보고서 cutoff보다
기준·공표·수집시각이 뒤인 레코드와 run은 제외합니다. GUI와 예약기는 SQLite connection을
공유하지 않습니다. lease·호출예산은 같은 DB의 앱 인스턴스만 조정하며, 다른 `--database`나
외부 프로그램까지 막지 않습니다. 보고서는 여러 짧은 읽기를 사용해 극히 좁은 외부 동시
변경을 하나의 transaction snapshot으로 고정하지는 않습니다.

놓친 16시 예약 보고서를 나중에 재실행할 때도 보고서 날짜와 자료 컷오프는 원래 예약시각에
고정합니다. 실제 생성시각은 별도로 보존하며, 예약시각 뒤에 공표·수집된 자료를 과거 날짜
보고서에 소급하지 않습니다. 수동 보고서는 사용자가 생성한 현재 시각을 컷오프로 사용합니다.

PC가 꺼진 동안에는 실행되지 않습니다. 재개가 예약시각 전이면 호출을 가장 최근 과거 슬롯에
귀속하지만, `Persistent=true`는 여러 날의 완전한 소급 수집을 보장하지 않습니다. OpenDART
공시는 최근 7일, ECOS와 OpenDART 재무는 설정된 고정 기간, Fed는 현재 RSS 범위만 조회하므로
장기 장애 뒤 누락된 기간을 모두 backfill하지 않습니다. 주문이 없으므로 catch-up은 주문 승인이나
밀린 거래 실행이 아닙니다.

Windows Task Scheduler XML은 소스에서 생성할 수 있고, 앱은 고정된 두 작업 이름을
`schtasks.exe /Query`로 읽기 전용 질의해 등록 여부를 표시합니다. 표시 언어에 의존하는
활성화·실행 상태는 추정하지 않습니다. 실제 Windows 등록·절전 복귀·한글 경로 및 상태
조회 검증은 **NOT RUN**입니다. 자세한 절차는 `WINDOWS_VALIDATION.md`에 있습니다.

## 기존 원장 불변조건

- 초기자산 400만 원은 상세 원장과 합산하지 않고 대조합니다.
- SAMPLE/MANUAL_PAPER_SNAPSHOT/MANUAL_ACTUAL은 한 원장에서 섞지 않습니다.
- 보호저축·비상금은 투자자산 분모에서 제외합니다.
- 코어 ±5%p 제안 점검과 전체 투자자산 대비 위성 10% 상한은 별도입니다.
- 위성 0%·10% 미만은 매수 의무가 아니며, 정확히 10%는 상한 도달, 초과는 신규 위성 매수
  중지입니다.
- 2027년에는 2028년 80:20 규칙을 자동 적용하지 않습니다.
- 사용자 자유 텍스트의 계좌번호형 문자열은 출력 전에 공통 마스킹합니다.
- 기존 7개 절 순서는 수동 보고서와 자동 보고서 모두 유지합니다.
