## 1. 통합 의사결정 (팀 합의사항 적용)

1. 작업 순서: **P0 데이터/원장 증거 모델 → 3개 주문 경로 공통 게이트 → 강제종료/UNKNOWN 복구**, 다만 **각 단계에 실패 재현·회귀 시험을 병행**합니다.
2. 적용 대상: 사용자별 **명시적으로 지정된 PAPER portfolio IDs**. 실제 직접기록 자산(USER_DECLARED_REAL), SAMPLE, 보호저축, 다른 사용자 자산은 시작 NAV·20% quota에 포함 금지합니다.
3. **Stage4 기존 5% 한도는 추가 보수 제한으로 유지**합니다. 이를 사용자 확정 정책으로 재해석하거나 20%로 상향하지 않습니다. 한도 겹침 시 **각 안전 검사를 모두 통과**해야 합니다.
4. 국내 거래의 미국 세션 공통 quota 정책이 미확정이면 **국내 자동 실행 차단**, 분석·조회만 허용합니다. 임의 세션 귀속이나 범위 외 거래로 quota 우회 금지.
5. 한도 계산에는 opening NAV의 원장 리비전, 평가 보유수량·현금, 확인된 quote/FX 출처, as_of/observed/collected 시각, 허용 지연, NYSE 휴장·DST/반일장·검증 해시가 필요합니다. **달력 PASS 또는 nav_source 문자열만으로 검증 완료 표시 금지**.
6. 기술팀 PR #27은 NAV 미검증 시 HTTP 409/Stage4 session_unverified/readiness false 차단을 구현했습니다. 이를 거래 기능 100% 완성 또는 유효한 당일 한도 확인으로 표현하지 않습니다.
7. 데이터·거래 안전을 완전히 통합하기 전 `readiness=true` 또는 우회용 환경변수를 추가해서는 안 됩니다. 자동 PAPER OFF, Draft 미병합, 운영 DB 보존, KIS/Windows/실거래 제외.

## 2. 시각/상태 계약

상태를 **(a) 조회 중, (b) 미확인/차단, (c) 명시적 허용+별도 검사, (d) 원장 기록 완료**로 분리합니다. 색깔만으로 표현하지 않고 짧은 한국어 상태 + 사유 + 다음 행동을 제공합니다.

| 실제 확인된 상태 | 화면 제목/본문 문구 | 행동·표시 제한 |
|---|---|---|
| `control.paused=true` | **PAPER 자동주문 중지** · 사용자 중지 상태입니다. | 시작 허용 버튼은 서버가 별도 재검증해야 하며 자동 체결 보장 문구 금지 |
| `control.paused=false`, `readiness.verified=false` | **거래 검증 미완료 · PAPER 실행 보류** · 사용자 중지는 해제됐지만 세션 시작자산 등이 아직 검증되지 않았습니다. | Stage4·승인 주문 실행 차단, '거래 가능' 배지 금지 |
| `control=null` / control 행·테이블 없음 / 조회 오류 | **거래 제어 상태 확인 불가** · 안전 확인 전 모든 PAPER 실행을 보류합니다. | 긴급중지 요청만 허용, 정상 허용처럼 표시 금지 |
| `readiness=null` / loading / API 오류 | **거래 준비 상태 확인 중/실패** · 실행 가능 여부를 확인하지 못했습니다. | 실행 버튼 비활성, 확인 후 재조회 안내 |
| `UNVERIFIED_SESSION_OPENING_NAV` | **시작 NAV 검증 대기** · 현금·보유주식·시세·환율·원장 확인이 완료되지 않았습니다. | 0원/4백만원/예시 80만원을 당일 잔여 한도로 표시 금지 |
| `US_MARKET_SESSION_NOT_VERIFIED_OR_CLOSED` | **미국 거래 세션 확인 불가/장외** · 거래일과 시간을 확인할 수 없습니다. | 실행 차단, 마지막 검증시각이 있으면 종류를 명시 |
| `GROSS_TURNOVER_CAP_EXCEEDED` | **PAPER 일일 20% 한도 초과** · 매수·매도·예약·미확정액 합산이 기준을 초과했습니다. | 검증된 분모·합계가 있는 경우에만 숫자 표시 |
| `PENDING` | **승인 대기 · 가상체결 전** | 승인 자체는 체결이 아님 |
| `APPROVED` | **승인 완료 · 가상체결 전** | 24시간 유효기한·거래 안전검사 별도 표시 |
| `RESERVED` / `CLAIMED` | **한도 예약 중 · 가상체결 완료 아님** | 동일 요청 중복 실행 금지 |
| `UNKNOWN` | **결과 미확정 · 예약 유지** · 원장을 대조하기 전 같은 주문을 다시 실행하지 마세요. | 성공/실패 단정 금지, 금액 자동 해제 금지 |
| `FILLED` (실제 원장 증빙 존재) | **PAPER 가상거래 기록 확인 · 실거래 아님** | receipt 및 원장과 대조된 경우만 성공 표시 |
| legacy/Stage4 claim 미대조 | **기존 주문 기록 대조 필요** · 주문이 중지됐습니다. | 자동 재주문 금지 |
| 수동자산 POST 응답 분실 | **저장 여부 미확정** · 중복 등록 방지를 위해 새 입력을 막고 기존 요청을 확인합니다. | 동일 ID 대조, 새로고침 후에도 fail-closed |
| POST 저장 확인/목록 GET 실패 | **기록 저장 확인 · 목록 조회 실패** · 재입력하지 말고 목록을 다시 불러오세요. | 저장 실패로 오인시키지 않음 |
| 인증 401/403·로그아웃 | **인증 확인 필요** · 금융정보를 표시하지 않습니다. | 카드/그래프/상세/알림/이전 사용자 데이터 비노출 |

**표시의 핵심:** `readiness.verified=false`인데 사용자 `paused=false`라는 이유만으로 **거래 허용**이라고 표시하지 않습니다. '설정상 허용'과 '실행 가능'은 별도 개념입니다. 새 응답 계약이 확정되기 전에는 최신 코드를 모르는 척 가상의 값이나 필드를 UI에 추가하지 않습니다.

## 3. 금액과 검증 표시 규칙

- 실측 시작 NAV: 같은 세션의 **검증된 원장 스냅샷·유효한 가격·환율·검증시각**을 결합했을 때만 표시합니다. 소급 가격이나 설정 시작금으로 채우지 않습니다.
- 초기 4,000,000원: **'설정된 초기 PAPER 입금 목표'** 또는 **'시험용 NAV'**로만 표시. 누적 입금 실적은 원장이 확인한 실제 값만 표시하며, 25일 350,000원 가상 적립/중복 방지는 원장으로 검증합니다.
- 환율/시세/원가/총자산/잔여 한도/손익: 미확인일 때 **'검증 대기'**, '산정 불가', '시세 미확인' 등으로 표시. **0, 0원, 0%를 결측의 대용으로 사용 금지**.
- OWNER PAPER의 미국/한국/ISA 포함 계좌 **ID 목록과 정책 버전**이 서버 계약으로 확인되어야 사용자 합계 표시. 화면의 계좌명으로 합산 범위를 추론하지 않습니다.
- PAPER, USER_DECLARED_REAL, SAMPLE은 배지/표/원장/API에서 서로 다른 scope. 실보유의 취득가 `null`과 실제 손익 0원 구분. 미확정 실자산은 PAPER 총합/수익률에 포함하지 않습니다.
- 20% 총량에 매수+매도+PENDING/RESERVED/UNKNOWN/FILLED를 **같은 거래 중복 없이** 반영. Stage4 5% 추가 한도는 개별 항목으로 안내하고 두 정책의 분모를 혼동하지 않습니다.
- 사용자에게 표시할 '사용 가능 금액'은 모든 검증 필드와 안전 정책이 통과된 경우에 한정하며, 실행은 항상 별도 서버 재검증해야 합니다.

## 6. 역할·파일 소유권과 완료 조건

- **기술팀:** verified NAV/FX/quote/NYSE 근거 및 공통 DB writer 게이트, Stage4·HTTP·USD FX 계약 구현. 공용 TSX의 API·state 가공·거래 버튼 로직도 담당. 변경 SHA/API 스키마/테스트 제출.
- **QA팀:** 각 단계부터 독립 격리 SQLite/TestClient·멀티프로세스·강제종료/UNKNOWN·원장/보안, 구형 수용시험 24건 현재시각 vs 역사적 고정시각 분리. 단위시험 PASS를 전체 수용 PASS로 승계 금지.
- **디자인팀:** 본 상태명세 및 사용자 문구 관리, 기존 화면/CSS/토큰/접근성 검수. 실제 Chrome 스크린샷 없이는 시각 PASS 표시 불가.
- **총괄팀:** owner 범위·국내 세션 quota/Stage4 5% 병행정책 최종 확인, 공용 변경 조정 및 QA·디자인 증거 후 배포 여부 별도 승인. 기존 Stage4 5%는 현재 **유지**하되 새로운 사용자 확정 정책으로 쓰지 않습니다.

**개별 작업의 완료:** 동일 SHA+API/DB 증거+화면 증거가 일치하고, 모든 P0 fail-closed와 역사적/현재시각 수용 시험을 통과한 경우.
